# 3D-просмотр товаров

Просмотрщик загружает GLB по запросу и поддерживает вращение мышью или касанием, масштабирование, автоматическое вращение и сброс ракурса. Управление с клавиатуры: стрелки, `+`, `−`, `Home`; `Escape` закрывает окно. Автоматическое вращение по умолчанию отключено.

Пробные AI-реконструкции сняты с публикации: мелкие детали и скрытые поверхности получились недостаточно качественными. Все текущие записи имеют `published: false`; магазин показывает фотографии без кнопок и значков 3D. Файлы сохранены для разработки, но не предлагаются покупателям.

Для качественного результата нужна модель соответствующего артикула: CAD от изготовителя, ручное моделирование по размерам и нескольким ракурсам либо качественный 3D-скан. Увеличение числа полигонов у пробной реконструкции не восстанавливает отсутствующие детали.

Кандидат для дальнейшего изучения: [сборка стартера КАМАЗ СТ142](https://vmasshtabe.ru/transport/auto-parts/starter-kamaz-st142.html). Автор указывает формат Inventor/STEP и отсутствие тягового реле; скачивание требует учётной записи. Соответствие товару, комплектность и разрешение на публикацию пока не подтверждены. Модель не скачана и не подключена к магазину.

## Устройство

- `src/model-manifest.json` — связь товара с моделью и исходной фотографией.
- `public/models/*.glb` — готовые модели, доступные со статического хостинга.
- `src/product-model.ts` — чтение реестра без загрузки 3D-библиотеки.
- `src/product-3d.tsx` — отдельный модуль Three.js, GLTFLoader и OrbitControls.
- `tests/product-3d.spec.ts` — загрузка, управление, повторное открытие и обработка ошибок.

Товары без готовой модели отображают обычную фотогалерею. При ошибке загрузки доступны повторная попытка и возврат к фотографиям. При закрытии освобождаются геометрия, материалы, текстуры, WebGL-контекст и обработчики событий. Скрытая вкладка не выполняет рендеринг сцены.

## Локальная генерация TripoSR

Источник модели: [официальный репозиторий TripoSR](https://github.com/VAST-AI-Research/TripoSR). Код и веса опубликованы под [лицензией MIT](TripoSR-MIT.txt). Генерация выполняется отдельно от Vite и Vercel; Python и веса нейросети не включаются в клиентскую сборку.

Пример установки в отдельном рабочем каталоге:

```sh
git clone https://github.com/VAST-AI-Research/TripoSR.git /path/to/TripoSR
uv venv /path/to/3d-env
uv pip install --python /path/to/3d-env/bin/python \
  torch==2.11.0 transformers==4.35.0 omegaconf==2.3.0 einops trimesh \
  'rembg[cpu]' imageio scikit-image 'numpy<2' numba==0.63.1
```

Запуск из корня проекта:

```sh
/path/to/3d-env/bin/python scripts/generate-local-models.py \
  --source /path/to/TripoSR turbo-tkr starter
```

При первом запуске скачиваются веса. Скрипт выбирает MPS на Apple Silicon, CUDA при наличии или CPU. Для явного выбора используется `--device`; `--resolution` задаёт разрешение извлечения поверхности, по умолчанию `160`. Извлечение поверхности использует scikit-image и не требует компиляции CUDA-расширений.

Готовые файлы сохраняются в `public/models/`, реестр обновляется после успешного экспорта с `published: false`. Уже зарегистрированные модели пропускаются. Исходные фотографии остаются без изменений.

Для повторной генерации используется `--force`. Ключ `--preview-dir /path/to/review` сохраняет результат отдельно и не меняет реестр магазина. Актуальные фотографии выбираются через `src/image-assets.json`; старые имена файлов продолжают работать в сохранённых корзинах и карточках товаров.

Скрипт извлекает поверхность с внешним направлением треугольников, проверяет нормали каждого компонента и экспортирует сглаженные нормали. Цвета фотографий преобразуются из sRGB в линейное пространство glTF. Направление поверхности контролируется тестом `tests/model-assets.spec.ts`: отрицательный объём указывает на ошибочно вывернутую модель.

## Генерация через TRELLIS.2

Альтернативный скрипт использует [официальную демонстрацию Microsoft TRELLIS.2](https://huggingface.co/spaces/microsoft/TRELLIS.2):

```sh
uv run --with gradio_client python scripts/generate-product-models.py turbo-tkr
```

Этот способ отправляет исходную фотографию в публичный сервис Hugging Face и зависит от доступности сервиса и GPU-квоты. Он предназначен для подготовки ассетов, а не для выполнения при открытии страницы покупателем. Платные API не подключены.

## Добавление готовой модели

Поместите самостоятельный GLB со встроенными ресурсами в `public/models/` и добавьте запись с идентификатором товара:

```json
{
  "product-id": {
    "src": "/models/product-id.glb",
    "generator": "supplier-cad",
    "sourceImage": "/images/product-photo.png",
    "published": false
  }
}
```

Перед публикацией проверьте артикул и комплектацию, геометрию со всех сторон, отверстия и крепления, материалы и резкость на мобильном экране. Подготовьте подпись, соответствующую происхождению модели: текущая подпись просмотрщика описывает AI-реконструкцию и требует замены для CAD. Только после проверки установите `published: true` и выполните `npm run build`. Запись без этого поля также скрыта. Права на исходные материалы проверяются отдельно от лицензии нейросети.

`tests/model-visibility.spec.ts` проверяет, что снятые с публикации модели не появляются в каталоге и карточках и не загружаются фоном. Проверки управления в `tests/product-3d.spec.ts` явно пропускаются, пока тестовая турбина не опубликована; прохождение технических тестов не означает достаточное визуальное качество модели.
